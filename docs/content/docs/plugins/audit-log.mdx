## Overview

The Audit Log plugin records authentication and admin actions to a dedicated
`auditLog` table and exposes query, export, and risk-alert endpoints for the
admin console (`admin.cinagroup.com`). It satisfies the audit/traceability
requirements of the CinaGroup financial-compliance ecosystem.

Events are captured via two complementary, non-overlapping paths:

1. **Automatic capture** — a whitelisted `hooks.after` matcher records core
   auth events (sign-in, sign-up, sign-out, password change, 2FA enable/disable,
  email-otp send/verify, SIWE wallet lifecycle, privacy export) and all `admin/*` mutations. No
   extra code is needed on those endpoints.
2. **Explicit capture** — the console proxy calls `POST /audit/log` for
   console-only actions (e.g. CSV export) that have no corresponding cinaauth
   endpoint.

Writes are **best-effort and non-blocking**: an audit failure is logged to
stderr and never breaks the auth flow it is recording.

## Installation

```ts
import { auditLog } from "cinaauth/plugins";

const auth = new CinaAuth({
	plugins: [
		auditLog({
			allowedRoles: ["admin", "security_admin"],
			writeTokens: [process.env.CINAUTH_ADMIN_SERVICE_KEY], // console proxy
		}),
		// ...admin, siwe, two-factor, email-otp, etc.
	],
});
```

### Options

- `allowedRoles` (default `["admin"]`) — roles permitted to query/export/alerts
  and to write via an authoritative fresh session (in addition to
  `writeTokens`). Session freshness follows `session.freshAge`; the plugin
  bypasses cookie cache for this sensitive write. Set `freshAge: 0` only when
  the deployment intentionally disables freshness checks globally.
- `writeTokens` (default `[]`) — bearer tokens permitted to call `POST /audit/log`
  without a browser session (e.g. the admin console's service key). This
  service-to-service branch is independent of session freshness. Token
  comparison is plain `includes` (acceptable for internal service tokens).
- `schema` — extend the `auditLog` table fields.

## Schema

```
auditLog
  id, timestamp (indexed), actorId (indexed), actorRole, actorIp, actorUa,
  actorSite, category (indexed), action (indexed), targetType, targetId (indexed),
  result, metadata
```

- `category` ∈ `user | session | auth | admin | risk | wallet | org | apikey | identity | authenticator | credential | privacy | integration | provisioning | billing | audit`
- `result` ∈ `success | failure`
- `metadata` — JSON string (event-specific details, e.g. wallet address/chainId)

Retention is enforced by a D1 lifecycle/cron cleanup (deployment config, not
code); rows are never deleted by the console.

## API

### List audit logs

**Server:** `auth.api.listAudit({ headers, query })`

```
GET /audit/list?limit=&offset=&start=&end=&category=&action=&actorId=&actorIp=&result=&targetId=&sortBy=&sortDirection=
```

Returns `{ rows, total, limit, offset }`. Requires an `allowedRoles` session.

### Write an audit log entry

**Server:** `auth.api.logAudit({ headers, body })`

```
POST /audit/log
body: { category, action, result, actorSite?, targetType?, targetId?, metadata? }
```

Auth: a bearer token in `writeTokens` **or** an authoritative fresh
`allowedRoles` session. The session branch re-reads stateful sessions from the
server-side store and rejects stale sessions with `SESSION_NOT_FRESH`. A valid
write token does not require a browser session. The actor (id/role/IP/UA) is
recorded from the request; service-token writes have no user actor id/role.

### Export audit logs as CSV

**Server:** `auth.api.exportAudit({ headers, query })`

```
GET /audit/export?start=&end=&category=&action=&actorId=&actorIp=&result=&targetId=
```

Returns a `text/csv` attachment (same filters as `/audit/list`, minus pagination,
capped at 100000 rows). Requires an `allowedRoles` session.

### Risk alerts

**Server:** `auth.api.auditAlerts({ headers, query })`

```
GET /audit/alerts?windowHours=&failThreshold=
```

Aggregates failures within `windowHours` (default 24) and returns actors whose
failure count meets `failThreshold` (default 10):

```json
{ "windowHours": 24, "failThreshold": 10, "flagged": [{ "actor": "...", "failures": 42 }] }
```

The actor key is `actorId`, falling back to `actorIp`, then `"anonymous"`.
Requires an `allowedRoles` session.

## Captured events

| Path | category | action |
| --- | --- | --- |
| `/sign-in/email`, `/sign-in/social` | auth | user.login / user.login_social |
| `/sign-up/email` | auth | user.register |
| `/sign-out` | auth | user.logout |
| `/change-password` | auth | user.password_change |
| `/two-factor/enable` `/disable` | auth | user.2fa_enable / user.2fa_disable |
| `/email-otp/send-verification-otp` `/verify-email` | auth | user.otp_send / user.otp_verify |
| `/siwe/verify`, `/siwe/link-wallet` | wallet | siwe.bind (carries `targetId`=user, `metadata.address`) |
| `/siwe/set-primary-wallet`, `/siwe/unlink-wallet` | wallet | siwe.set_primary / siwe.unbind |
| `/admin/ban-user` `/unban-user` | admin | admin.user_ban / admin.user_unban |
| `/admin/create-user` `/update-user` `/remove-user` `/set-user-password` | admin | admin.user_* |
| `/admin/set-role` | admin | admin.set_role |
| `/admin/impersonate-user` | admin | admin.impersonate |
| `/admin/revoke-user-session(s)` | session | session.revoke / session.revoke_all |

Success vs. failure is derived from the endpoint response (`getEndpointResponse`
returns null for non-200/APIError → `result: "failure"`).
